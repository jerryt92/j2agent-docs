# 构建与启动

## 1. 后端打包

在仓库根目录执行（与 [`docker/j2agent/Dockerfile`](../../j2agent/docker/j2agent/Dockerfile) 注释一致）：

```bash
mvn -f j2agent/pom.xml -pl j2agent-model -am -DskipTests install
mvn -f j2agent/pom.xml -pl j2agent-starter -am -DskipTests package
```

产物：`j2agent-starter/target/j2agent-*.tar.gz`，解压后为 `j2agent/classes`、`j2agent/lib` 等，**不含** `dist/`。

## 1.1 镜像构建时如何找到 tar.gz

[`docker/j2agent/Dockerfile`](../../j2agent/docker/j2agent/Dockerfile) 按以下**优先级**选取后端包：

| 优先级 | 路径 | 适用场景 |
|--------|------|----------|
| 1 | `docker/j2agent/*.tar.gz`（与 Dockerfile **同级**） | 离线机、仅拷贝部署包、CI 产物分发 |
| 2 | `j2agent-starter/target/*.tar.gz` | 本机开发，刚执行过 `mvn package` |

### 方式 A：开发机构建（默认）

在 `j2agent/` 模块目录完成 Maven 打包后，直接构建镜像，Dockerfile 会自动使用 `target/` 下的产物：

```bash
# 仓库根目录
mvn -f j2agent/pom.xml -pl j2agent-model -am -DskipTests install
mvn -f j2agent/pom.xml -pl j2agent-starter -am -DskipTests package

cd j2agent/docker
docker compose up -d --build
```

### 方式 B：预置 tar.gz（推荐离线 / 无 Maven 环境）

将 Java 打包得到的 `j2agent-*.tar.gz` **复制到 Dockerfile 同级目录** `docker/j2agent/`，再构建镜像。目标机**无需**安装 Maven，也**不必**携带完整源码的 `target/` 目录。

```bash
# 在有 Maven 的机器上打包（或在 CI 产出制品）
mvn -f j2agent/pom.xml -pl j2agent-model -am -DskipTests install
mvn -f j2agent/pom.xml -pl j2agent-starter -am -DskipTests package

# 将产物放到 Dockerfile 同级（文件名示例，以实际版本为准）
cp j2agent/j2agent-starter/target/j2agent-*.tar.gz \
   j2agent/docker/j2agent/

# 构建并启动（可在离线机执行，需已 docker load 基镜像，见离线文档）
cd j2agent/docker
docker compose up -d --build
```

目录示意：

```text
j2agent/docker/j2agent/
├── Dockerfile
└── j2agent-1.0.0.tar.gz   # 与 Dockerfile 同级，构建时优先使用
```

若同级目录与 `target/` 下**同时存在** tar.gz，**以同级目录为准**。

## 2. 构建并启动 Compose

```bash
cd j2agent/docker
cp .env.example .env   # 首次
# 编辑 .env
docker compose up -d --build
```

- `j2agent` 镜像名：`j2agent:${TAG}`
- 构建上下文：`j2agent/`（compose 中 `context: ..`）；Dockerfile：`docker/j2agent/Dockerfile`
- 后端包：优先 `docker/j2agent/*.tar.gz`，否则 `j2agent-starter/target/*.tar.gz`（见 [§1.1](#11-镜像构建时如何找到-targz)）

## 3. 关键环境变量

| 变量 | 说明 |
|------|------|
| `SPRING_OPTIONS` | 必须包含 `--spring.profiles.active=product`，否则静态资源走 `classpath:/ui/`，宿主机 `ui` 卷不生效 |
| `J2AGENT_PORT` | 应用容器端口，仅供 Compose 网络内 Nginx 反代 |
| `J2AGENT_NGINX_PORT` | Nginx HTTPS 宿主机端口 |
| `J2AGENT_HTTP_REDIRECT_PORT` | Nginx HTTP 宿主机端口 |
| `J2AGENT_ENFORCE_HTTPS` | `true` 时 HTTP 返回 308 到 HTTPS；默认 `false`，直接反代 HTTP |
| `J2AGENT_VOLUMES_PATH` | 宿主机数据根目录 |
| `I18N` | **必填**。种子数据与 Flyway 语言目录（如 `zh_CN` → `sql/data/postgresql/zh_CN.sql`、`sql/migration/postgresql/zh_CN`）；须与 `application-product.yaml` 中 `I18N: ${I18N}` 一致 |
| `JAVA_OPTS` | JVM 参数 |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | PostgreSQL 初始化库名与用户（默认 `j2agent`），表结构由应用 bootstrap |
| `J2AGENT_DB_HOST` / `J2AGENT_DB_PORT` / `J2AGENT_DB_USERNAME` / `J2AGENT_DB_PASSWORD` | 应用连接 PostgreSQL（Compose 内默认 `postgres:5432`） |
| `ETCD_IMAGE_TAG` / `ETCD_PORT` | Milvus 外置 etcd 镜像与宿主机映射端口 |

智能体全局配置不在 Docker 环境变量中维护，请在管理界面 **设置 → 智能体全局配置** 中编辑并保存（持久化至 `ai_properties.agent-global-config-json`）。

完整列表见 [`docker/.env.example`](../../j2agent/docker/.env.example)。

Milvus 依赖外置 `etcd` 服务健康后再启动（`depends_on: service_healthy`）。

## 3.1 数据库初始化（首次空库）

PostgreSQL 容器首次启动时，`POSTGRES_DB` 只会创建**空数据库**，不会执行任何 SQL 文件。

`j2agent` 在 Flyway 迁移之前会自动检测空库（`public` schema 下无 `api_key_info` 表），并按顺序执行：

1. `sql/schema/postgresql/schemas.sql` — 建表
2. `sql/data/postgresql/${I18N}.sql` — 种子数据（与 `.env` 中 `I18N` 一致）
3. Flyway — `sql/migration/postgresql/${I18N}/` 下增量脚本（如 `V0_1__agent_global_config.sql` 插入 `agent-global-config-json`）

因此 **无需** 在 Compose 中挂载 `docker-entrypoint-initdb.d` SQL。若需完全重建库，停止栈后删除宿主机 `${J2AGENT_VOLUMES_PATH}/volumes/postgres`，再重新 `docker compose up`。

**Flyway 路径说明**：

| Profile | `spring.flyway.locations` | `I18N` 来源 |
|---------|---------------------------|-------------|
| 本地开发（`application.yaml`） | 硬编码 `classpath:/sql/migration/postgresql/zh_CN` | bootstrap 脚本语言由 Java `${I18N:zh_CN}` 决定 |
| 生产（`application-product.yaml`） | `classpath:/sql/migration/postgresql/${I18N}` | **必须**由 `.env` / 容器环境变量 `I18N` 注入（如 `zh_CN`） |

生产环境若未设置 `I18N`，Flyway 可能扫描不到迁移脚本（日志出现 `No migrations found` 或仅 baseline），`object_file` 等表不会创建。请确认 `.env` 含 `I18N=zh_CN` 且 compose 已传入 `j2agent` 容器。

**首次部署后**：表结构就绪后，须在管理端配置 LLM 与 Embedding 当前生效项，见 [LLM 提供商配置 §1.0](../../平台/LLM提供商配置/README.md#10-首次部署与启动日志)。

## 3.2 启动日志判读（常见误判）

| 日志 | 含义 | 是否异常 |
|------|------|----------|
| `Successfully validated N migrations` + `Current version ... 0.2` | 建表与 Flyway 已完成 | 正常 |
| `Schema "public" is up to date` | 无待执行迁移 | 正常（非空库重启） |
| `未找到生效中的 LLM/Embedding 配置` | `api_provider_config` 尚无当前项 | **预期**（首次部署），去设置页配置 |
| `Flyway upgrade recommended: PostgreSQL 18` | Flyway 未正式声明支持 PG 18 | 可忽略 |
| `No migrations found` | `I18N` 未注入或 Flyway 路径错误 | **异常**，检查 `.env` 中 `I18N` |

## 4. 启动后检查

```bash
docker compose ps
docker compose logs -f j2agent
docker compose exec j2agent sh -c 'echo $SPRING_OPTIONS'
curl -k -s -o /dev/null -w "%{http_code}\n" "https://127.0.0.1:${J2AGENT_NGINX_PORT}/index.html"
```

`SPRING_OPTIONS` 应含 `product`；`index.html` 返回 200 表示 `volumes/j2agent/ui` 已挂载且可读。

首次空库启动时，日志中应出现 `Applying SQL bootstrap` 与 Flyway `Current version of schema "public": 0.2`（或 `Successfully applied`）。

配置 LLM 前若出现 `未找到生效中的 LLM 配置`，属首次部署正常现象，见 [LLM 提供商配置](../../平台/LLM提供商配置/README.md#10-首次部署与启动日志)。

## 5. 仅更新后端

修改 Java 代码后重新 `mvn package`，再构建 `j2agent` 镜像。

**开发机**（使用 `target/` 产物）：

```bash
cd j2agent/docker
docker compose up -d --build j2agent
```

**已采用预置包**（`docker/j2agent/*.tar.gz`）时，先覆盖同级 tar.gz 再重建：

```bash
cp j2agent/j2agent-starter/target/j2agent-*.tar.gz \
   j2agent/docker/j2agent/
cd j2agent/docker
docker compose up -d --build j2agent
```

前端仅更新 `dist` 目录时**不必**重建镜像，见 [前端静态资源更新.md](./前端静态资源更新.md)。

## 6. 停止与清理

```bash
docker compose down          # 停止并删除容器，保留卷数据
docker compose down -v       # 若 compose 定义了 named volume 会一并删除（当前主要为 bind mount，数据在宿主机 J2AGENT_VOLUMES_PATH）
```
