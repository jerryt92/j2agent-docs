# 用户与权限

本文档归档 **j2agent** 的用户数据模型、登录会话、角色鉴权与用户管理 REST API。邮箱自助注册见 [邮箱注册机制.md](./邮箱注册机制.md)。

## 用户模型

### 数据表

库表 `app_user`（[`schemas.sql`](../../j2agent/j2agent-server/src/main/resources/sql/schema/postgresql/schemas.sql)）：

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | `char(32)` PK | UUIDv7（[`UUIDv7Utils`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/utils/UUIDv7Utils.java)） |
| `username` | `varchar(64)` NOT NULL | 登录名 |
| `password_hash` | `char(64)` NOT NULL | `SHA256(userId + password)` |
| `create_time` | `bigint` | 创建时间戳 |
| `role` | `int` | `1` 系统管理员，`2` 知识库管理员，`3` 普通用户 |
| `email` | `varchar(128)` NULL | 邮箱；唯一索引 `uq_user_email` |

密码算法见 [`UserUtil`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/utils/UserUtil.java)：`getPasswordHash(userId, password)` / `verifyPassword`。

### 内置管理员

种子数据 [`sql/data/postgresql/zh_CN.sql`](../../j2agent/j2agent-server/src/main/resources/sql/data/postgresql/zh_CN.sql) 插入：

- `username` = **`aiadmin`**
- `role` = `1`（管理员）
- 固定 `id`：`AZ5EsB1JcMqXv6z1FcfEUw`

[`UserService`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/service/security/UserService.java) 中常量 `BUILTIN_ADMIN_USERNAME = "aiadmin"`，对该用户：

- 不可删除
- 不可修改角色
- 其他管理员不可为其重置密码（`updateUserPassword` 中 `ensureMutableUser`）

## 角色与鉴权

### 角色枚举

[`UserRoleEnum`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/model/security/UserRoleEnum.java)：

| 枚举 | 值 | 说明 |
|------|-----|------|
| `ADMIN` | 1 | 系统管理员 |
| `KNOWLEDGE_ADMIN` | 2 | 知识库管理员：维护知识库、分配普通用户的库级授权 |
| `USER` | 3 | 普通用户 |

**数值越小权限越高。** 判断能否访问某接口要求：

```text
userContext.role.value <= requiredRole
```

要求 `ADMIN(1)` 时仅系统管理员通过；要求 `KNOWLEDGE_ADMIN(2)` 时系统管理员与知识库管理员均可通过；要求 `USER(3)` 时三者均可通过。

`userContext.isAdmin()` 等价于 `hasAccess(ADMIN)`；`userContext.isKnowledgeAdmin()` 等价于 `hasAccess(KNOWLEDGE_ADMIN)`（含系统管理员）。

角色与 `permissions`（预留细粒度权限）存储在 Redis，由 [`UserLoginContextCache`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/service/security/UserLoginContextCache.java) 管理，**不写入 JWT**。

### @RequiredRole 注解

[`RequiredRole`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/config/security/RequiredRole.java) 标注在 Controller 类或方法上：

| 常量 | 值 | 含义 |
|------|-----|------|
| `UserRoleEnum.ADMIN` | 1 | 仅系统管理员 |
| `UserRoleEnum.KNOWLEDGE_ADMIN` | 2 | 系统管理员与知识库管理员 |
| `UserRoleEnum.USER` | 3 | 已登录即可（含上述角色） |

未标注时，[`LoginInterceptor`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/interceptor/LoginInterceptor.java) 默认按 `USER(3)` 校验。

### LoginInterceptor

配置于 [`InterceptorConfig`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/config/web/InterceptorConfig.java)：

- 拦截：`/v*/**`
- 排除：`/v*/auth/**`（登录、验证码、邮箱注册等公开接口）

流程：

1. [`LoginInterceptor`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/interceptor/LoginInterceptor.java) 调用 `LoginService.resolveRequest`：从 `Authorization: Bearer` 或查询参数 `authorization` 读取 JWT，验签并 `bindSession`。
2. 未登录：**401**，并 `clearSession`。
3. 已登录但角色不足：**403**，并 `clearSession`。
4. 请求结束：`afterCompletion` 中 `clearSession`，避免线程池复用导致会话串号。

WebSocket 握手通过查询参数 `authorization` 传递 token，由 [`WebsocketLoginInterceptor`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/interceptor/WebsocketLoginInterceptor.java) 校验。

## 资源授权

资源授权独立于登录角色：系统管理员与知识库管理员可进入知识库管理界面并调用知识库 REST API；普通用户**不能**访问知识库大菜单及 `/knowledge/**` 接口，仅能在对话/智能体链路中凭 `user_knowledge_permission` 授权做服务端检索。公开只提供读取或使用能力，不提供管理权限。Agent 授权不能代替知识库授权。

### 数据与权限矩阵

| 存储 | 关键字段与含义 |
|------|----------------|
| `user_agent_permission` | `user_id`、`agent_id`；`permission_level=2` 固定表示使用 |
| `user_knowledge_permission` | `user_id`、`knowledge_repository_id`；`1` 管理、`2` 只读 |
| 两张授权表公共字段 | 主键 `id`、用户与资源联合唯一约束、资源反查索引；`expires_at` 为毫秒时间戳，NULL 表示永久；`created_at`、`updated_at` |
| `knowledge_repository` | `creator_user_id` 表示创建者，`is_public` 表示是否公开 |
| `agent_access_config` | 按 `agent_id` 独立保存 `is_public`，不依赖个人授权缓存 |

| 操作 | 普通用户条件 |
|------|--------------|
| 使用 Agent | Agent 公开或存在未到期的等级 2 授权 |
| 对话/智能体内检索知识库 | 存在未到期等级 1/2 授权，或目标库公开（`ChatService` / `Retriever` 服务端校验） |
| `GET /knowledge/collections` | 已登录即可；**仅返回当前用户可读** collection，供问答选库，非管理端 |
| `/file/repo/**`、`/file/static/**` | 已登录且 `requireSource` 通过（来源文件预览） |
| 知识库管理界面与 `/knowledge/repositories/**` 等管理 REST | **不允许** |
| 读取知识库（管理端列表/正文） | 不允许（仅知识库管理员或系统管理员） |
| 修改配置、单库同步 | 不允许（仅知识库管理员或系统管理员） |
| 知识库授权、公开设置、删除 | 不允许（由知识库管理员在管理端操作） |
| 创建知识库 | 不允许（仅知识库管理员或系统管理员） |
| 知识库全局同步/完全重建、同步状态 | 系统管理员与知识库管理员 |
| Agent 授权、插件管理、系统配置 | 不允许，仅系统管理员 |

创建者身份来自仓库字段，不在授权表中写等级 0；等级 3“仅经业务 Agent 读取”不再使用。历史会话保留，重新执行请求或打开引用文件仍按当前权限检查。

### 用户名输入与 userId 存储

所有 Agent、知识库权限分配界面和授权接口均以 `username` 作为用户输入和展示值：

- `PUT/DELETE /v1/rest/j2agent/agents/{agentId}/permissions/{username}`
- `PUT/DELETE /v1/rest/j2agent/knowledge/repositories/{repositoryId}/permissions/{username}`
- 授权列表返回 `username`、`permissionLevel`、`expiresAt`、`expired`，不返回授权对象的 `userId`。

服务端通过 `ResourcePermissionMapper.findOrdinaryUserId(username)` 查询 `app_user.id`，只允许 `role=3` 的普通用户，然后把解析出的 `userId` 写入授权表和权限缓存。也就是说：**输入/展示是用户名，数据库与 Redis 的关联键仍是稳定的 userId**；不存在的用户名、管理员用户名不会被当作授权对象。

### 角色、所有权与删除语义

| 角色/身份 | Agent | 知识库管理 | 知识库读取 | 授权对象限制 |
|---|---|---|---|---|
| 系统管理员 `ADMIN(1)` | 管理 | 管理全部知识库 | 读取全部知识库 | 可给普通用户分配 Agent/知识库权限 |
| 知识库管理员 `KNOWLEDGE_ADMIN(2)` | 使用权限仍由 Agent 规则决定 | 管理全部知识库 | 读取全部知识库 | 可给普通用户分配知识库权限，不能分配 Agent 权限 |
| 普通用户 `USER(3)` | 公开或有效等级 2 授权 | 无管理 API 权限 | 公开、本人创建或有效等级 1/2 授权 | 不能作为授权接口操作者 |
| 知识库创建者 | 不因创建者身份获得管理角色 | 普通用户不能绕过管理接口 | 可按创建者条件读取 | 创建者不是授权表中的等级 0 |

当前代码中 `KnowledgeRepositoryController` 要求 `KNOWLEDGE_ADMIN`，且删除知识库使用 `requireRepository(..., level=0)`；因此系统管理员和知识库管理员都可以删除知识库，普通用户即使是创建者也不能通过该管理 API 删除。删除知识库时会先清理向量、目录和关联授权，最后删除 `knowledge_repository` 记录。

删除用户时，`user_agent_permission.user_id` 和 `user_knowledge_permission.user_id` 的外键 `ON DELETE CASCADE` 会删除其授权记录；Redis 用户权限缓存也会在删除流程中清理。知识库不会因为创建者被删除而删除：`knowledge_repository.creator_user_id` 使用 `ON DELETE SET NULL`，库配置和内容保留，但失去创建者身份条件，后续仍按公开、授权和管理员规则鉴权。

### 查询过滤

`ResourceAccessService` 先取得有效授权 ID，再在 SQL 中构造条件：

`读取：is_public=true OR creator_user_id=:uid OR id IN (:kbReadIds)`

`管理：creator_user_id=:uid OR id IN (:kbManageIds)`

管理员不追加这些条件；授权集合为空时只省略 IN 分支，不能省略整个过滤条件。Agent 内存注册表使用集合交集过滤。当前仓库列表查询返回过滤后的全部记录，尚无分页参数，不能将此理解为已完成分页与总数查询验收。

### Redisson 用户权限缓存

下表 key 均带项目 `RedisKeyNamespaces` 前缀；花括号中的 userId 是 Redis hash tag，同用户的数据和锁同槽。

| Key 后缀 | 类型 | 内容 |
|----------|------|------|
| `acl:{userId}:agent:2` | `RScoredSortedSet<String>` | Agent 使用授权 |
| `acl:{userId}:kb:1` | 同上 | 知识库管理授权 |
| `acl:{userId}:kb:2` | 同上 | 知识库读取授权，同时写入等级 1、2 |
| `acl:{userId}:loaded` | `RBucket<String>` | 应存在的集合索引：0=agent:2、1=kb:1、2=kb:2；空字符串表示已完整加载但无授权 |
| `acl:{userId}:lock` | `RLock` | 用户级串行锁，独立使用 Watchdog |

集合 member 为资源 ID，score 为授权到期毫秒；永久授权 score 为有限值 `Double.MAX_VALUE`，不是 Redis 的无穷值。读取使用 `score > 当前时间`，缓存续期不会延长授权期限。公开与创建者信息每次依据数据库判断，不冗余到个人授权集合。

数据 key 使用 30 分钟滑动 TTL。每次权限读取对三个集合及加载标记使用同一个绝对 `expireAt` 时间；不存在的空集合不创建占位成员。发布、读取续期和清理采用 `RBatch` 的 `IN_MEMORY_ATOMIC` 模式，不使用普通 pipeline，不自行编写 Lua，也不混用登录缓存的 StringRedisTemplate。

`ResourcePermissionCache` 的加载和变更流程：

1. 获取用户锁，最多等待 5 秒；使用 Watchdog，不指定短固定租期。
2. 读取时检查 loaded 及其中声明的集合；不完整才在锁内查询两张表并完整发布。随后读取有效成员、统一续期。
3. 变更时先删除全部用户权限数据 key，成功后开启数据库事务并提交，再删除一次。只清缓存，不增量更新集合；事务回滚后保留缓存缺失状态。
4. 同一执行线程在 finally 中检查持锁后释放。Redis/锁故障拒绝请求，不无锁回源；业务检索、LLM 和维护不在权限锁内执行。

登录及身份缓存回源后，`PermissionWarmup` 异步预热；预热未完成时，首次权限使用按相同锁同步加载。合法空授权由 loaded 标记区分，不因三个集合都空而反复查库。

当前后置清理失败会向调用方抛错，数据库可能已经提交；专门的告警与重试机制尚未补齐。多实例撤权、Redis 故障、绝对 TTL 与进程退出仍需集成验收，不应将上述实现说明视为测试通过记录。登录身份缓存保持原机制，本次没有追加其并发治理。锁也不追溯中断已通过鉴权的单次业务操作，不提供极端故障下的跨系统强一致。

### 授权与公开 API

两组资源前缀分别为 `/v1/rest/j2agent/agents/{id}` 与 `/v1/rest/j2agent/knowledge/repositories/{id}`。

| 方法 | 前缀后的路径 | 含义 |
|------|--------------|------|
| GET | `/permissions` | 授权列表，含 username、permissionLevel、expiresAt、expired |
| PUT | `/permissions/{username}` | 新增、修改等级或续期；只允许普通用户作为授权对象；成功 204 |
| DELETE | `/permissions/{username}` | 撤销授权；成功 204 |
| GET | `/visibility` | 查询 isPublic |
| PUT | `/visibility` | 提交布尔字段 isPublic；成功 204 |

PUT 授权必传 `permissionLevel`；知识库取值 `1=管理、2=只读`，Agent 固定取值 `2=使用`。`expiresAt` 显式为 null 表示永久，传数字必须晚于当前时间。省略时保留旧期限，新授权省略则永久。续期复用 PUT，不存在独立 renew 接口。Agent 接口仅系统管理员可用；知识库授权、公开设置和管理 REST 由系统管理员或知识库管理员操作，普通用户/普通创建者不能因拥有创建者身份绕过角色校验。

### 升级迁移

`V0_3__resource_permissions.sql` 创建授权表及任务表，保留角色 `2`（知识库管理员）；迁移时已有知识库设为公开，创建者为空。Agent 注册表首次授权初始化会将当时已注册 Agent 设为公开，后续新增默认私有。新建知识库默认私有；自动发现目录无创建者，不据此推定某个普通用户为所有者。升级前应备份数据库，并单独核验已有登录/API Key 身份缓存的角色刷新，本次迁移 SQL 不处理 Redis 身份缓存。

委派候选及执行鉴权见 [子智能体调用与记忆](../通用助手/子智能体调用与记忆.md)，仓库检索边界见 [检索](../RAG机制/检索/README.md)，单库任务见 [知识库维护](../RAG机制/知识库维护/知识库维护.md)。

## 登录与 JWT

### 登录

- **接口**：`POST /v1/auth/j2agent/login`（[`LoginController`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/controller/LoginController.java)）
- **请求体**：`username`、`password`、`validateCode`、`hash`（滑动验证码，与注册发码相同机制）
- **成功**：`200` + `AuthResultDto`（`token`、`expiresIn`），JWT 与外部系统（`platsvc-security` / `platsvc-gateway`）共用密钥与 claims 结构（配置前缀 `j2agent.security.jwt`）
- **失败**：401

### JWT（登录凭证，与外部系统算法互通）

登录签发、请求验签均通过 [`JwtService`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/jwt/JwtService.java) 完成，配置前缀 `j2agent.security.jwt`，算法与 claims 与外部系统（`platsvc-security` / gateway）一致。**JWT 仅负责登录校验（验签 + 身份标识），role/permissions 从 Redis 读取。**

| Claim | 说明 |
|-------|------|
| `user` / `name` | 用户 ID / 用户名 |
| `sid` | 会话标识，用于 Redis 缓存键 |
| `terminal` | `BROWSER` |
| `classify` | `system` |
| `auth` | `auth-pc`（外部系统终端鉴权） |

| 行为 | 说明 |
|------|------|
| 登录 | 返回 `{ token, expiresIn }`；同时将 `UserContextBo`（含 role、permissions）写入 Redis |
| 鉴权 | 验签 JWT → 按 `sid` 读 Redis；缓存 miss 或过期则从 DB 重建，TTL = JWT 剩余有效期 |
| 登出 | 客户端丢弃 token；服务端删除 `login:ctx:{sid}` |
| 改密/删用户/改角色 | `invalidateUserLogin` 删除该用户全部 sid 缓存；下次请求从 DB 重建 |

### Redis 用户上下文缓存

[`UserLoginContextCache`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/service/security/UserLoginContextCache.java) 使用 `StringRedisTemplate` + JSON 序列化 `UserContextBo`：

| Key | 类型 | 值 | TTL |
|-----|------|-----|-----|
| `{appName}:login:ctx:{sid}` | String | `UserContextBo` JSON（含 role、permissions） | JWT `expiresIn`（登录时）或 JWT 剩余秒数（重建时） |
| `{appName}:login:user-sids:{userId}` | Set | 该用户活跃 `sid` 集合 | 与 ctx 同步刷新 |

**外部系统互通**：`j2agent.security.jwt` 的 `algorithm`、`secret`、`kmac-output-length-bytes` 须与外部系统（`com.nms.jwt` / `platsvc-security`）**完全一致**，否则验签失败返回 401。开发环境可通过环境变量覆盖：

- `J2AGENT_JWT_SECRET` — 与外部系统相同的密钥（支持 `base64:` 前缀）
- `J2AGENT_JWT_KMAC_OUTPUT_LENGTH_BYTES` — 与外部系统签发时一致（常见 `64` 或 `256`）

### 外部系统 SSO 跳转

前端与外部系统共用 localStorage 键 `access_token`。跳转方式：

| 场景 | URL 示例 |
|------|----------|
| 同域（共享 localStorage） | `https://host/j2agent/#/agents` |
| 跨域 / 不同端口 | `https://host/j2agent/?authorization=<jwt>#/agents` |

启动时 [`consumeLaunchQueryFromUrl`](../../j2agent-ui/src/utils/launchQuery.ts) 统一解析并剥离 URL 启动参数（当前含 `authorization` → `access_token`；新参数在此模块扩展）；[`bootstrapSessionFromToken`](../../j2agent-ui/src/utils/auth.ts) 带 Bearer 调 `GET /v1/rest/j2agent/session`，触发后端验签与自动注册。已在 `/login` 且 token 有效时自动跳主页。

**注意**：j2agent 鉴权失败时**不会**删除 `access_token`，避免破坏外部系统会话；仅 [`Logout.vue`](../../j2agent-ui/src/pages/login/Logout.vue) 主动登出时清除。

**排障**：若跳转后仍 401，优先检查 JWT `secret` 与 `kmac-output-length-bytes` 是否与外部系统一致；用浏览器 Network 查看 `/session` 响应码。

### 外部 Token 自动注册

外部系统携带**合法 JWT** 访问时，若本库不存在 JWT `user` claim 对应的主键，[`UserService.provisionExternalUser`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/service/security/UserService.java) 在 [`LoginService.loadAndCacheContext`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/service/security/LoginService.java) 中自动建档：

| 字段 | 规则 |
|------|------|
| `id` | 直接沿用 JWT claim `user`（trim 后非空且长度 ≤ 32） |
| `username` | 来自 JWT claim `name`；为空则回退为 `userId`；若用户名已占用则追加 `_{6位随机小写字母+数字}` |
| `role` | 固定 `3`（普通用户） |
| `password_hash` | 随机密码哈希（仅 SSO/JWT 登录，不可本地密码登录） |

**不再**按 `name` 回退匹配本地已有用户名，避免外部 token 误绑本地同名账号。`user` claim 缺失或非法时仍返回 401。

Redis miss 时流程：验签通过 → 按 `user` 查 DB → 不存在则自动注册 → 写入 Redis 缓存。

## API Key 认证与管理

API Key 用于服务端、CLI 等程序化访问，使用与 JWT 相同的请求头：

```http
Authorization: Bearer apikey-<keyId>.<secret>
```

Bearer 值以 `apikey-` 开头时走 API Key 校验；其他 Bearer 值继续按 JWT 验签。为兼容浏览器 WebSocket（无法设置自定义 Header），`authorization` 查询参数也可传 JWT 或 API Key；常规 REST / CLI 请求仍建议使用 Authorization Header，避免密钥出现在 URL、访问日志或代理日志中。每个 Key 创建一个独立的 API 专用用户，角色（ADMIN / USER）即该 Key 的有效权限；专用用户不允许密码或 JWT 登录，也不会出现在常规用户管理列表。

完整 Key 仅在创建时返回一次。数据库仅保存完整 API Key 的 SHA-256 哈希与可公开的前缀。Key 自身由 256 位随机密钥组成，没有固定过期时间；管理员删除 Key 时，关联的 API 专用用户一并删除，认证缓存同步失效。

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/v1/rest/j2agent/api-keys` | ADMIN | 列出脱敏 API Key |
| POST | `/v1/rest/j2agent/api-keys` | ADMIN | 创建 Key 与专用用户，返回完整 Key 一次 |
| PUT | `/v1/rest/j2agent/api-keys/{id}/role` | ADMIN | 修改专用用户角色 |
| DELETE | `/v1/rest/j2agent/api-keys/{id}` | ADMIN | 删除 Key 与专用用户 |

API Key 校验结果缓存在 Redis 30 分钟，并在每次成功请求时续期；改角色或删除 Key 时立即清除缓存。不要记录或传播完整 Key。

实现：[`UserController`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/controller/UserController.java) + [`UserService`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/service/security/UserService.java)。

OpenAPI：[`openapi-interface.yaml`](../../j2agent/j2agent-model/src/main/resources/openapi-interface.yaml)（`User` tag）。

| 方法 | 路径 | @RequiredRole | 说明 |
|------|------|---------------|------|
| GET | `/v1/rest/j2agent/users` | ADMIN | 用户列表，`create_time DESC, username ASC` |
| POST | `/v1/rest/j2agent/users` | ADMIN | 创建用户；body：`username`、`password`、可选 `role`（默认 USER） |
| DELETE | `/v1/rest/j2agent/users?user-id=` | ADMIN | 删除用户；内置 `aiadmin` 不可删 |
| PUT | `/v1/rest/j2agent/users/role` | ADMIN | 修改角色；`userId` + `role`（1、2 或 3） |
| PUT | `/v1/rest/j2agent/users/password` | USER | 修改密码；见下表 |

### 修改密码规则

请求体 `UserPasswordUpdateRequestDto`：`userId`（可选）、`newPassword`。

| 操作者 | 目标 | 规则 |
|--------|------|------|
| 普通用户 | 自己（`userId` 省略或等于当前用户） | 允许修改 |
| 普通用户 | 他人 | **403** |
| 管理员 | 自己 | 允许修改 |
| 管理员 | 他人 | 允许重置；**不可**修改 `aiadmin` |

改密、删用户、改角色后，[`UserService`](../../j2agent/j2agent-server/src/main/java/io/github/jerryt92/j2agent/service/security/UserService.java) 调用 `invalidateUserLogin` 清除 Redis 缓存；旧 JWT 在 `exp` 到期前仍可通过验签，但下次请求会从 DB 读取最新 role（用户已删则 401）。

## 用户创建途径对比

| 途径 | 接口 / 入口 | 角色 | 说明 |
|------|-------------|------|------|
| 迁移脚本 | SQL | ADMIN | 仅 `aiadmin` |
| 管理员创建 | `POST .../users` | 可指定 1 或 3 | 需管理员登录 |
| 邮箱自助注册 | `POST .../register` | 固定 USER(3) | 见 [邮箱注册机制.md](./邮箱注册机制.md) |
| 外部 JWT 首次访问 | 携带合法 Bearer token | 固定 USER(3) | JWT `user` 不在 DB 时自动注册，见上文 |

自助注册用户可用邮箱（或注册时指定的 `username`）登录；`email` 字段写入 `user.email`。
